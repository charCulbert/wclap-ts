Getting started

WCLAP audio plug-ins (CLAP compiled to WebAssembly) on your own web page. This site is a plain project that installs wclap-ts the way yours would; each example below is one HTML file with its code shown underneath, ready to copy.

1. Install

npm install github:charCulbert/wclap-ts

The library starts its AudioWorklet and Workers from the files beside it in node_modules/wclap-ts/dist/, so there is nothing to copy as long as your server serves node_modules.

2. Serve

Plug-ins use shared memory, which browsers allow only on a cross-origin-isolated page. Send these two headers from your server:

Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

Where you can't (GitHub Pages, a plain static server), a service worker adds them. It has to sit beside your pages, so copy it there once, and call await isolate() first; the page reloads once. These examples do that, so any static server works:

npx wclap-ts setup --sw .   # copies wclap-sw.js here
npm start                   # a plain static server (serve.mjs), then open http://127.0.0.1:8160/

3. Import

With a bundler (Vite, esbuild…), import { loadWclap } from "wclap-ts" works. Without one, an import map does it, as in these pages:

<script type="importmap">{ "imports": { "wclap-ts": "/node_modules/wclap-ts/dist/index.js" } }</script>

If your bundler moves the library and leaves its dist/ files behind, copy them to a folder you serve (npx wclap-ts setup public/wclap) and pass base: "/wclap/".

4. The examples

1 · One plug-inA synth with its own interface, a piano, parameter events, saving its sound. 2 · A chainSequencer → synth → delay in one node; bypass and tempo while it plays. 3 · A/BTwo synths, every note on the same frame, switched with a crossfade. 4 · Effect and automationAny Web Audio source into an effect, a generated parameter panel, a sample-accurate sweep. 5 · MIDIMIDI keyboards in, a mod wheel mapped to a parameter, notes coming out. 6 · Render to a fileThe same API offline: a synth's sequence rendered faster than real time to a WAV. 7 · Your own graphA kick and an acid bassline on a shared transport, routed by your own AudioWorklet module: a send bus and latency compensation. 8 · A synth in a windowWith compost: its interface in a draggable window, a piano, a meter and a scope. 9 · A rackWith compost: a strip of number boxes per plug-in, every parameter, kept in sync both ways, bypass switches, interfaces in windows.

The shape of it

import { loadWclap, createChain, createHost, isolate } from "wclap-ts";

await isolate();                                             // only without the headers
const context = new AudioContext();                          // after a click
const synth = await loadWclap(context, "/plugins/MySynth.wclap.tar.gz", { ui: document.querySelector("#ui") });
synth.connect(context.destination);
synth.noteOn(60, 0.8);                                       // or at an exact AudioContext time
synth.addEventListener("param", (e) => console.log(e.detail));

const chain = await createChain(context);                    // several plug-ins in series, one node
await chain.add("/plugins/Arp.wclap.tar.gz");
await chain.add("/plugins/MySynth.wclap.tar.gz");

The examples load PICOH-101, Pro54, Slide and Tapa straight from GitHub (charCulbert/char-wclaps): any URL that allows cross-origin requests works. Hive, a note sequencer, comes from andremichelle/open-webclap, and a test gain plug-in (from char-clap-template, MIT) is in plugins/ here. Pro54 is Cmajor's example synth, GPL-3.0, loaded from its own URL and not included here. Swap in your own .wclap.tar.gz files.
